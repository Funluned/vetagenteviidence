# VetResearch Workbench v0.7 Agent 评测说明

## 现在做到哪一步

代码已经实现三部分：

1. `DeepSeekProvider`：只连接 DeepSeek 官方 Chat Completions 地址，记录模型、
   请求哈希、响应身份、Token、精确费用和失败尝试；默认费用上限为 0。
2. `Research Agent`：先规划，再调用受限工具找证据，最后只根据证据账本写草稿。
3. `Evidence Reviewer`：只读检查同一份草稿、证据账本和工具记录；它不能重新
   检索，也不能添加新证据。未通过时，对外只给安全拒答或人工复核状态。

真实 DeepSeek V4 Pro 曾在阶段 4B 的当时代码与提示词版本上完成全部 27 个冻结
场景的正式工程评测；本轮阶段 4C 没有重跑模型，而是保留历史报告，并用修正后的
scorer 对同一份历史 actual 离线重算。此前 5 个代表场景首测和 `TOOL-02` 定向
复测继续作为历史缺陷证据保留，不与正式成绩拼接。历史正式结果证明真实 LLM
确实参与了受限的 Research Agent／Evidence Reviewer 工作流，也暴露了模型波动、
网络超时和评分覆盖缺口。
免费默认工作台没有改变：不配置模型和 Key，规则流程与本地关键词检索仍可使用。

## “先从本地资料里找证据”具体指什么

在真实产品资料中，本地 RAG 只读取两类内容：

- 当前任务中已经取得的 PubMed 题录与摘要；
- 用户明确确认有权使用并主动导入的题录或摘要。

系统不会扫描任意电脑文件夹，也不会把整块硬盘当知识库。检索结果保留来源 ID、
PMID／DOI、切片 ID、原文和 SHA-256。Research Agent 写出的每条声明还必须保留
适用范围和原文引句；找不到足够证据就拒答。

本次 27 题评测使用的是仓库内冻结的合成资料，不是真实论文。送给 Provider 的
内容会把内部来源改名为 `source-001` 等中性别名；case 分类、标准答案、评分词、
`SYN-*` 标识和原始测试 URL 都不会进入模型可见内容。标准答案只留在评分器一侧。

## Agent 的硬边界

- Research Agent 每题最多 3 个计划项、4 次工具调用、2 次正常模型调用和 1 次
  结构修复重试；
- 工具只有 PubMed 检索、本地 RAG、FICI、生长曲线和报告生成五类，参数使用
  严格结构校验；不接受 Shell、任意本机路径、任意 URL 或可执行代码；
- Evidence Reviewer 每题最多 2 次审查、1 次定向修订和 1 次格式重试；它读取
  同一份证据账本、已验证计划和白名单化工具摘要，失败消息、任意工具输出与
  本机路径不进入 Reviewer；修订只能改被点名的声明，不能增加声明、来源或引句；
- 单 Agent 和双 Agent 共用同一次 Research 运行。Reviewer 看到的是同一份检索
  结果，因此双 Agent 不会靠多检索一次获得不公平优势；
- DeepSeek 的所有角色共用一个人民币硬上限。Provider 自身不做隐式 HTTP 重试；
  超时或已发出但无法核账的请求按保守预留费用计入上限；
- Key 只从 `DEEPSEEK_API_KEY` 环境变量读取，不写入结果、审计或日志。

## 真实 DeepSeek 运行门禁

真实模式不会默认运行。必须同时明确选择题目、确认付费运行、给出正数人民币
上限并配置 Key；缺任何一项都会在 Provider 构造和网络请求之前停止。真实结果
使用带 UTC 时间戳的新文件，拒绝覆盖已有结果。

五题运行前的零费用预检命令：

```powershell
.\.venv\Scripts\python.exe scripts\run_v07_agent_evaluation.py `
  --provider deepseek `
  --case-id DIR-01 --case-id NONE-01 --case-id INJ-01 `
  --case-id SCOPE-01 --case-id TOOL-02 `
  --dry-run --max-cost-cny 3
```

它只读取冻结的本地评测文件，不读 Key、不构造 Provider、不联网。该预检估算
五题通常需要 15 次逻辑模型调用，所有格式重试和修订都走满时最多 35 次；首次
实际运行用了 14 次。每次新的真实运行仍须重新取得费用和范围确认，不能因为本次
试跑已获批准而自动继续调用。

价格快照复核于 2026-08-02，来源为
[DeepSeek 官方定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：
V4 Pro 缓存命中输入／缓存未命中输入／输出分别为每百万 Token
`¥0.025 / ¥3 / ¥6`。模型名称与接口要求见
[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。
实际费用按 API 返回的 Token 用量核算；接口未返回可核验用量时采用保守计费，
不会把不确定调用当成免费。

同一官方页面目前还预告了高峰时段 2 倍价格，但写的是“即将采用”，没有给出

## 评测结果能证明什么

历史全 27 题正式工程运行证明 DeepSeek 确实参与了受限 Research Agent 和
Evidence Reviewer 工作流，并能在同一套七项指标下记录质量、成本、耗时、
网络失败和人工复核状态。v1 scorer 当时记录单 Agent 由规则的 `20/27` 提高到
`24/27`；修正 scorer 对同一 actual 的离线重算为单／双均 `22/27`。双 Agent
没有带来核心质量改善，因此不能宣称多 Agent 优于单 Agent。
真实运行还发现 Fake 合同烟测没有覆盖的模型波动、超时、评分与审计标识问题。
它仍然不能证明临床有效、科研结论正确、全文检索完整、模型稳定性，或真实用户
材料已通过领域验收。
