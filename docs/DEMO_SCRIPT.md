# VetResearch Workbench v0.5 演示脚本

建议时长：8 分钟。使用仓库自带的合成导入、实验和网络关系演示文件，
文献检索使用真实 NCBI PubMed。

## 0:00—0:30 问题与定位

“VetEvidence AI v0.1 已经解决了真实 PubMed 检索、结构化提取和逐条引用。
VetResearch Workbench v0.5 在这个底座上完成问题拆解、多来源证据、实验
数据分析、公开数据库、网络药理学和带人工门禁的批量分子对接、决策报告与
人工审计。当前只聚焦候选药物与抗生素协同作用，不做诊断，也不把计算预测
当成实验事实。”

打开 `http://localhost:8501`，指出顶部七步标签：

1. 问题与假设；
2. 文献证据；
3. 实验数据；
4. 数据库证据；
5. 机制预测；
6. 决策报告；
7. 运行记录。

## 0:30—1:10 问题与假设

1. 先选择“证据不足负例”：`quercetin` 与 `amoxicillin` 对 `Streptococcus agalactiae` 是否具有值得进一步验证的协同作用；
2. 点击“创建或重置研究任务”；
3. 展示系统生成的 2—4 条假设、验证方法、成功标准和生成规则；
4. 轻微修改一条假设并保存；
5. 强调修改会写入运行记录，自动生成的 PubMed 检索式对用户可见。

讲解要点：

> 问题拆解使用透明规则，不依赖 LLM；用户可以在检索前审阅和修改假设。

## 1:10—2:10 多来源文献证据

1. 切换“文献证据”；
2. 点击“执行 3 轮 PubMed 检索”；
3. 展示负例结果：8 篇文献全部只能作为间接背景，直接文献证据为 0；
4. 生成报告，指出系统明确写出“仅凭本次文献检索不能判断或宣称存在协同作用”，而不是强行下结论；
5. 选择“公开直接文献证据正例”，执行 `florfenicol + thiamphenicol / Pasteurella multocida` 检索；
6. 展示本次复跑中唯一通过严格准入的 PMID `31749775`，打开详情核查 DOI、摘要、直接证据理由及原句；
7. 说明本次复跑中的其余结果仍可展示，但只能作为背景，不能进入协同结论。

讲解要点：

> “当前检索未发现直接文献证据”不等于“已经证明不存在协同”。真实、匹配药物对的实验 CSV 使用独立证据链呈现；数量和排序会随 PubMed 更新，结论必须限定在当前可见检索结果。

> 合成 RIS 只用于演示解析与条件提取，不是科研事实；系统不会绕过知网权限自动抓取。

## 2:10—3:10 实验条件与 CSV

1. 切换“实验数据”；
2. 展示统一实验条件矩阵：来源、物种、模型、样本量、干预、剂量、时间、对照、指标和缺失字段；
3. 展开一致性、显式冲突与证据空白；
4. 选择 `FICI`，点击“分析合成 FICI 演示”；
5. 展示逐行 FIC/FICI、分类、有效行数和原始行；
6. 指出合成演示当前产生 2 行协同和 1 行相加结果；
7. 如需切换演示，选择“生长曲线”，展示时间点均值、标准差和分组 AUC。

讲解要点：

> FICI 和生长曲线都是描述性分析。FICI 不能替代独立重复与 time-kill；AUC 不能替代预先登记的统计推断。

> 坏行不会被静默忽略，原始值、CSV 行号和错误都会进入审计。

## 3:10—3:40 数据库证据

1. 切换“数据库证据”，填写 TaxID，并用公开标识查询 PubChem、UniProt 或
   RCSB PDB；
2. 展示规范化记录、映射状态、来源链接、访问时间、版本和原始响应
   SHA-256，下载 JSON 与完整校验 ZIP；
3. 勾选外发确认后查询一组公开 STRING 标识，展示实验、人工整理、文本挖掘
   与预测通道分层；指出综合分数只用于排序；
4. DAVID 使用明确目标集和背景集；未配置注册邮箱时展示离线请求，不生成
   虚构富集结果。

讲解要点：

> 数据库记录和网络关联可追溯，但不等同于目标或通路已经实验验证；零结果
> 只说明当前查询没有返回记录。

## 3:40—6:20 机制预测

1. 切换“机制预测”；
2. 展示化合物—靶点和靶点—通路的 CSV、Excel、Word 模板，说明两张关系表
   均支持 CSV、XLSX、DOCX；XLSX 只接受一个非空工作表，DOCX 只接受一个
   非空表格；
3. 点击“加载合成网络演示”，展示两个带 `SYNTHETIC` accession 的数据源、
   输入 SHA-256、交集靶点和透明网络分数，再下载 XLSX 结果和 DOCX 报告；
4. 强调这些靶点和导出文件是流程演示，不是科研事实；
5. 进入“科研级批量对接”，先填写 RCSB PDB ID、UniProt accession、NCBI
   TaxID 与来源；上传原始受体结构和准备后 PDBQT；
6. 逐项确认模型、链、替代构象策略、水、辅因子/金属和其他异源原子的保留/
   移除决策，并填写搜索口袋依据。故意修改一个受体文件或搜索框，展示旧审批
   失效，再恢复并重新审批；
7. 展示配体的两类身份：PubChem CID + InChIKey，或带来源哈希的用户命名空间；
   上传多个已准备 PDBQT。Open Babel 基础准备可用于单个输入，但其 3D、pH
   质子化与 Gasteiger 电荷不能代替化学状态人工复核；
8. 输入多个 seed，生成“配体 × seed”的独立任务。若演示机已配置 Vina，
   指出实际版本、可执行文件位置和 SHA-256，并在用户确认后执行；
9. 展示每次尝试绑定的任务清单、seed、`run.log`、`poses.pdbqt`、预测评分、
   程序身份与各文件 SHA-256。强调任意日志、pose 或分数错配都会拒绝汇总；
10. 查看各 seed 的预测评分、均值、标准差和极差。明确当前没有计算跨 seed
    RMSD 或构象簇，评分稳定也不代表采样收敛；
11. 打开固定本地 3Dmol.js 视图，确认复合物只含已选择的受体内容和唯一配体
    chain/resid；下载可编辑 PML；
12. 只有在页面再次确认后，才调用用户另行安装并已核验的 Open-Source PyMOL
    或 PLIP。展示 PNG 完整解码状态；PSE 若未被同一 PyMOL 重开验证，必须显示
    `generated_unverified`；没有外部程序时使用 PML/复合物下载和 3Dmol.js
    降级路径；
13. 同时指出备用路径：“仅生成 Vina 任务清单”后可外部运行，但只有任务
    哈希、版本、日志和 pose 强绑定后才会形成可视化包。外部导入不能仅凭格式
    证明 Vina 确实运行过。

讲解要点：

> 网络排名与对接得分始终标为计算预测。即使 Vina 由 Agent 在本机成功运行并
> 完整留痕，也不能单独证明结合、抗菌活性或协同。

> Vina 显示的是预测评分，不是实验结合能。PDBQT 转成 PDB 会损失部分键级、
> 电荷和原子类型，所以 3D 图和 PLIP 相互作用只能作启发式检查。

> Open Babel 的 3D、pH 质子化和 Gasteiger 电荷只是受控的基础配体准备，
> 不能替代对互变异构体、立体化学、质子化状态、可旋转键和构象的人工核查。
> Open Babel 使用 GPL-2.0-only；仓库不捆绑其 wheel 或二进制，二次分发须
> 另做许可证合规。

> 项目不捆绑 Vina、Open Babel、Open-Source PyMOL 或 PLIP；这些程序由用户
> 另行合法安装。仓库只包含固定版本的 3Dmol.js 资产及许可证/上游元数据。

## 6:20—7:10 决策报告与人工复核

1. 切换“决策报告”；
2. 点击“生成或刷新决策报告”；
3. 展示可检验假设、可追溯结论、冲突、证据空白、风险和下一步建议；
4. 指出文献结论后的 PMID、DOI 或来源片段，以及 CSV 结论中的文件名、SHA-256、原始行号和计算过程；
5. 强调合成分析结论带有“不可作为科研证据”标签；
6. 下载 Markdown 或 JSON 审计报告；
7. 输入复核意见，选择“要求修改”或“通过”，保存人工复核。

讲解要点：

> 没有可追溯来源时系统拒绝生成报告。报告只能帮助确定下一步实验，不是诊疗或临床建议。

## 7:10—7:40 运行记录与恢复

1. 切换“运行记录”；
2. 展示当前状态、事件数、工具调用数和失败记录；
3. 查看问题拆解、PubMed 检索、文献导入、CSV 分析、报告生成与人工复核事件；
4. 指出本地文件 `.workbench/runs/<run_id>.json`；
5. 下载完整运行快照；
6. 复制页面显示的完整运行 ID，在“恢复历史运行”输入并恢复。

如果需要演示失败与重试，可上传一个缺少必需列的 CSV，查看失败事件后改用模板重试；失败记录不会因后续成功而消失。

## 7:40—8:00 验证与复盘

展示与当前改动相关的自动化回归和定向评测均已通过，并打开测试文件说明
网络格式适配、结果导出、Open Babel 单配体准备、受体人工门禁、类型化身份、
批量多 seed、Vina 强绑定、3Dmol.js/PyMOL/PLIP 降级和审计留痕的覆盖范围。
补充展示 AutoDock Vina 官方 `1IEP` 技术烟测记录，并明确其只验证执行链，
不属于本项目兽医科研证据。

总结：

- v0.1 保留了真实 PubMed、分区、透明提取、引用和 30 条定向评测；
- v0.5 跑通了问题、文献、实验、数据库证据、机制预测、报告、审计恢复
  七步闭环；
- 机制预测支持 CSV/XLSX/DOCX 输入、XLSX/DOCX 导出、受体审批、类型化
  身份、批量多 seed、强绑定 Vina 产物、本地 3Dmol.js、可编辑 PML，以及
  用户确认后的可选 Open-Source PyMOL/PLIP；
- 当前没有引入 LLM、多 Agent 框架、FastAPI 或向量数据库；
- 下一步是用真实、可公开且来源许可清楚的靶点关系、经研究者核查的配体/受体
  结构和已核验 Vina 环境进行人工验收。

主动说明：自动化测试和定向评测都是受控工程验证，不代表通用科研准确率。
