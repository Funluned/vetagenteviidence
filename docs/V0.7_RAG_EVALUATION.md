## 固定评测设计

现有 27 题中只有 `DIR-01`、`DIR-02`、`DIR-03` 和 `TOOL-02` 明确声明了
`gold_relevant_ids`，共 5 个正确来源。评测只从 `cases.json` 读取这些标签，
不读取 `expected.json`、`gold_rationale`、边界说明或禁止词来构造查询和文档。

每题候选池由本题正确来源加同一组 11 个硬负例固定构造，因此有 12 或 13 个唯一
来源，明确大于 `K=3`。正文只使用题名和摘要；来源 ID、URL、case ID、gold
标签和查询上下文不进入待检索正文。`TOOL-02` 的失败分支不入索引，两个成功
分支均保留。因为候选池构造时知道 gold，本指标只能称为“固定候选池内排序
Recall@3”，不能称为端到端文献检索召回或通用 RAG 准确率。

结果分为两个切片：

- `semantic_direct`：三条直接证据，分母 3；
- `resilience_partial`：`TOOL-02` 的两个成功分支，分母 2。它衡量部分失败后
  是否保留结果，不能解释成纯语义向量能力。

## Recall@3 结果

| 模式 | 总体 | `semantic_direct` | `resilience_partial` |
|---|---:|---:|---:|
| 仅关键词 BM25 | 4/5 | 3/3 | 1/2 |
| 仅本地特征哈希向量 | 2/5 | 2/3 | 0/2 |
| 关键词＋特征哈希混合 | 3/5 | 3/3 | 0/2 |

结论是：当前本地特征哈希向量没有给关键词基线带来增益，混合检索相对关键词
反而少命中 1 条。因此它只能作为“不新增模型、API 订阅或云向量库依赖”的
可复现向量管线基线，不能宣传为“语义 RAG 已有效”。当前产品不再规划自带的
本地语义模型：免费默认路径继续使用透明的关键词检索；真实 LLM 只在隔离的
Agent 评测入口验证，不改变这条检索基线的结论。

## 本地索引与安全边界

- 使用标准库 SQLite 保存来源、切片和向量，不引入云向量数据库或月租服务；
- 每个切片保存来源 ID、PMID／DOI、标题、字段位置、数据版本、授权范围和
  SHA-256；来源清单、切片清单和向量字节分别绑定哈希；
- 关键词和向量都在本机精确计算，同分按 `chunk_id` 固定排序；
- 只允许 `public`、`licensed`、`user_authorized` 三种授权范围；
- 所有文档正文固定标记为 `untrusted_evidence`。其中即使出现
  `Ignore previous instructions` 或 `SYSTEM:`，也只是待检索数据，没有工具、
  Shell、文件或网络执行权；
- 固定评测会封锁环境变量和网络访问；Fake LLM 与内置本地特征哈希 Provider
  不读取 API Key。真实模型调用、Token、模型 API 费用和网络使用均为零；
- 本地特征哈希的 `embed()` 仍会在 CPU 上运行，它不是训练模型调用；
- 上述离线保证只覆盖仓库内置 Provider。`LocalRAGIndex` 对自定义 Provider 的
  `network_used` 只是接口契约检查，不是进程级断网沙箱；
- 这条路径仍需要 Python、Pydantic、本机 CPU、磁盘，并以普通 SQLite 文件
  保存证据正文；当前没有静态加密，也不验证调用方声明的授权范围是否真实；
- “模型 API 与订阅费用为零”不代表计算机、电力、磁盘和人工复核没有成本。

## 工作台免费路径

阶段 3A 第二批已把该索引接入 Streamlit 的“文献证据”页。默认只索引当前任务
中带摘要的 PubMed 记录；用户导入摘要必须逐次确认有权用于本机索引。固定上限
为 500 个来源、500 万字符，结果固定 Top 3。因为当前评测中关键词最好，页面
默认 `keyword_only`；特征哈希向量和混合模式明确标为实验模式。

用户没有任何模型 Key 时，现有规则工作流和本地索引／检索仍可运行。实时获取
PubMed 摘要需要普通网络连接，但不产生模型 API 费用；已经存在于当前任务中的
摘要或用户授权导入摘要可完全在本机建立索引和检索。候选只供人工审查，不生成
回答、不自动进入科研结论。查询审计只保存 SHA-256，不保存原始问题文本。
