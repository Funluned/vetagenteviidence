# VetResearch Workbench v0.5 产品需求文档

## 1. 产品定位

VetResearch Workbench 基于 VetEvidence AI v0.1，把科研问题、可核查文献、
实验数据、公开数据库、网络药理学和分子对接组织成一个可审计的科研决策
闭环。

当前首个垂直场景只处理：

> 候选药物与抗生素对目标病原菌是否存在值得进一步验证的协同作用？

系统辅助科研证据整理和实验设计，不提供医疗或兽医诊断、处方或临床决策。

## 2. 产品演进

### VetEvidence AI v0.1：已验证技术底座

v0.1 已完成真实 PubMed 检索、期刊分区、摘要级结构化提取、带引用回答、Markdown/CSV 导出和定向评测。该版本证明了“检索—提取—引用—导出”的可追溯闭环。

### VetResearch Workbench v0.2：已验证科研闭环

v0.2 不再停留在“查论文”，而是把问题与假设、多个文献来源、实验条件、实验 CSV、冲突与空白、决策报告和人工复核串联起来，并保存全过程审计记录。

### VetResearch Workbench v0.3：机制预测底座

v0.3 修正文献目的句误判、交互结局冲突和 CSV 范围错配，并增加独立的
计算预测层：用户可从 CSV、XLSX 或 DOCX 导入带来源的化合物—靶点与
靶点—通路关系，生成透明网络排名并导出 XLSX/DOCX；保存 AutoDock Vina
任务参数前，用户可上传已准备的配体 PDBQT，或由固定版本 Open Babel
把单个常见化学结构文件转换为 PDBQT；任务可导入与清单绑定的用户输出，也可
由 Agent 受控执行已核验的本机 Vina。计算预测不得替代直接文献或实验结果。

### VetResearch Workbench v0.4：公开数据库证据层

v0.4 在本地文件导入之外，增加 PubChem、UniProt、NCBI Gene/GenBank、
RCSB PDB、STRING 与 DAVID 的用户主动查询。每次请求保存稳定标识、TaxID、
请求参数、数据库版本或发布日期、访问时间、原始响应 SHA-256 与不可覆盖
归档。STRING 各证据通道分层展示，综合分数只用于排序；DAVID 富集必须带
目标集、明确背景集、物种、原始 P 值和 BH 校正后 P 值。外发标识需要用户
确认，缺少配置时生成离线请求而不是伪造在线结果。

### VetResearch Workbench v0.5：科研级批量对接与可视化

v0.5 把原有“可运行 Vina”升级为“能回答产物是否属于这次已审批任务”的
科研链：受体必须经过模型、链、替代构象、水、辅因子/金属与异源原子处理的
人工门禁；配体和受体使用类型化稳定身份；批量配体与多个 seed 的每次尝试
都强绑定任务清单、程序身份、日志、构象、预测评分和哈希。固定本地
3Dmol.js 用于三维查看，PML 保持可编辑；Open-Source PyMOL 与 PLIP 仅在用户
明确确认后作为可选外部程序运行。全部产物仍为
`computational_prediction`。

## 3. 用户问题

科研人员形成实验判断时通常需要在多个界面和文件之间手工完成：

- 把宽泛问题拆成可验证假设；
- 扩大候选池，按各查询原始排名公平合并、去重，并在页面截断前优先保留能回答当前问题的文献；
- 比较不同论文中的样本、剂量、时间、对照和指标；
- 识别结论冲突及未报告条件；
- 计算 FICI 或比较生长曲线；
- 整理化合物—靶点—通路关系并保存数据库版本；
- 记录对接结构、搜索框、软件版本和原始输出；
- 把文献证据、实验数据、风险和下一步写成报告；
- 记录失败、重试和人工复核。

这些步骤一旦失去来源对应关系，就容易把摘要推断、合成演示数据或未经核查的导入记录误当成事实。

## 4. v0.5 目标

- 将一个协同作用科研问题拆成 2—4 条透明、可人工修改的假设；
- 以统一稳定标识和 TaxID 查询六类公开数据库，并保存可重放、可校验的来源
  归档；
- 把实验、人工整理、文本挖掘和模型预测关联分开，禁止用综合排名分数替代
  证据通道；
- 富集分析固定记录目标集、背景集、映射损失、原始 P 值与多重校正结果；
- 生成并执行最多 3 轮可见 PubMed 检索式，扩大候选池后保留各轮相关性顺序，以轮询方式公平合并并按 PMID 去重；
- 将每篇题名和摘要分为直接文献证据、间接背景或主题不匹配，并保留命中字段、判定理由和判定原句；
- 直接文献证据为 0 时生成明确的文献证据不足报告，不把间接背景包装成协同文献结论；
- 支持 RIS、EndNote、RefWorks 导入及 DOI/标题年份去重；
- 统一展示 PubMed 与用户导入来源，不为非 PubMed 来源伪造 PMID；
- 建立固定字段实验条件矩阵，显式报告缺失值、方向冲突和证据空白；
- 对 FICI 与生长曲线 CSV 做逐行校验和描述性计算；
- 强制问题正文、结构字段、实验 CSV 和机制预测使用相同药物与研究对象；
- 从目的、假设、方法和阈值定义中区分真实交互结果，并识别直接文献中的协同/拮抗冲突；
- 对 CSV、XLSX 或 DOCX 格式、带来源 accession、版本和哈希的关系表执行透明网络药理学排名，并导出 XLSX 结果和 DOCX 报告；
- 用可选的 Open Babel 3.2.1 把单个、最大 10 MB 的 SMI/SMILES、SDF、MOL、MOL2 或 PDB 配体转换为经校验的 PDBQT，并直接进入 Vina 任务；
- Open Babel 配体准备只开放是否生成三维坐标和可选 pH 质子化，部分电荷固定使用 Gasteiger；成功记录输入/输出哈希、版本、可执行文件哈希、受控参数、退出码和耗时；
- 生成不含分数的 Vina 任务清单；既支持解析任务哈希与版本一致的外部输出，也支持用户确认后由 Agent 受控执行已核验的本机 Vina；
- 本机 Vina 成功执行必须记录版本、可执行文件 SHA-256、参数、退出码、耗时、绑定日志及输出 PDBQT 哈希；
- 受体审批必须绑定原始结构与准备后 PDBQT，并明确模型、链、替代构象、水、
  辅因子/金属、其他异源原子、准备工具与搜索口袋依据；任一内容变化后审批
  失效；
- 配体身份必须是 PubChem CID/InChIKey，或带来源哈希的显式用户命名空间；
  受体身份必须保留 RCSB PDB ID/UniProt accession、NCBI TaxID 与来源哈希；
- 支持多个配体和多个 seed；每次尝试独立记录，且预测评分只能从与任务清单、
  日志和输出构象哈希一致的已验证产物派生；
- 固定本地 3Dmol.js 资产及其许可证/上游元数据；生成只含所选受体内容和唯一
  配体选择器的复合物与可编辑 PML；
- Open-Source PyMOL/PLIP 只能在用户明确确认后调用；PNG 通过完整解码才可用，
  PSE 未经同一已核验 PyMOL 重开验证时降级为 `generated_unverified`；
- 多 seed 汇总只报告 Vina 预测评分的描述性稳定性；不声称当前未计算的跨
  seed RMSD 或构象簇；
- 在报告中单列计算预测及其局限，不让预测成为协同结论的证据；
- 输出带证据、风险、空白、下一步和人工复核的科研决策报告；
- 持久化任务事件、工具调用、失败和复核结果，并支持凭完整运行 ID 恢复；
- 保持 v0.1 的检索、提取、引用、分区和评测能力可用。

## 5. 非目标

- 不自动抓取知网或绕过任何平台权限；
- 不读取未授权全文，不支持扫描 PDF/OCR；
- 不覆盖所有实验类型，首个闭环只支持 FICI 和生长曲线；
- 不自动进行显著性推断、模型选择或因果判断；
- 不自动下载或猜测化合物靶点、通路和蛋白结构；
- 不用 Open Babel 自动准备受体，也不把一次通用格式转换视为完成了科研级结构准备；
- 不捆绑或下载 AutoDock Vina、Open Babel、Meeko、Open-Source PyMOL 或
  PLIP；也不执行未核验或未经用户确认的二进制程序；仓库只捆绑固定版本的
  3Dmol.js 前端资产、许可证和上游元数据；
- 仓库不捆绑 Open Babel wheel 或二进制；它仅作为 `GPL-2.0-only` 的固定版本可选依赖，二次分发前须另做许可证合规；
- 不把网络排名或对接得分视为结合、药效或协同证明；
- 不把 Vina 预测评分称为实验结合能，不用不存在的跨 seed RMSD、构象簇或
  未验证 PSE/PNG 增强结论；
- 不把动物、体外或摘要级结果直接外推到临床；
- 不训练或微调大模型；
- 不在 v0.2 引入多 Agent 框架、FastAPI、向量数据库、账号权限或云端协作；
- 不把合成演示数据当作科研证据；
- 不允许未经过人工复核的报告成为最终决策。

## 6. 核心用户流程

1. 用户输入科研问题、研究对象、候选干预、联合药物和预设指标；
2. 系统用透明规则生成 2—4 条可检验假设，用户可修改；
3. 系统生成并执行最多 3 轮 PubMed 检索，扩大候选池后保留各轮相关性顺序，以轮询方式公平合并、PMID 去重并按证据等级稳定分桶；
4. 用户可额外导入 RIS、EndNote、RefWorks 题录，系统规范化并去重；
5. 系统按研究对象、两种干预和交互指标执行透明证据分级，再将所有可见来源整理为实验条件矩阵；
6. 系统识别直接文献证据准入状态、摘要级一致性、显式方向冲突和实验条件空白；
7. 用户上传 FICI 或生长曲线 CSV，系统逐行校验身份范围并执行描述性分析；
8. 用户从 CSV、XLSX 或 DOCX 导入网络关系并可导出 XLSX/DOCX 结果；分子
   对接先完成受体人工审批和类型化身份绑定，再为多个配体、多个 seed 生成
   Vina 任务；系统只汇总强绑定的日志、构象和预测评分，并提供本地 3Dmol.js、
   可编辑 PML 及经再次确认的可选 PyMOL/PLIP 产物；
9. 系统生成分层展示正式证据、实验结果和计算预测的决策报告；
10. 用户选择通过、要求修改或拒绝；
11. 系统把全过程写入 `.workbench/runs/<run_id>.json`，可在页面恢复。

## 8. 数据与引用契约

- PubMed 文献以 PMID 为主要身份，同时保留 DOI、摘要片段和来源 URL；
- 用户导入文献使用稳定来源 ID，可有 DOI，但 PMID 缺失时必须保持为空；
- 文献结论至少关联 PMID、DOI、来源 URL 或原文片段中的一项；
- 直接交互文献证据必须在同一题名或摘要句中同时命中研究对象、两种干预、交互指标和明确结果；`combination` 单词、纯方法或阈值描述、检索轮次或期刊分区都不能单独作为准入依据；
- 实验分析保留 CSV 原始行、行号、有效性和错误信息；进入报告时必须同时记录文件名、SHA-256、数据行与计算过程；
- 无效或部分无效 CSV 不进入结论和建议，并在报告中形成明确证据空白；
- FICI 与生长曲线每一有效行都必须匹配当前问题的两种干预与研究对象；
- 网络关系输入支持 CSV、XLSX 和 DOCX；XLSX 只接受一个非空工作表，DOCX 只接受一个非空表格，输入仍须满足固定列契约并记录文件 SHA-256；
- 网络结果可导出 XLSX 和 DOCX；导出必须保留来源、输入哈希、靶点排名和通路关系，且不改变 `computational_prediction` 证据等级；
- 机制关系、配体、受体、Vina 参数和原始输出必须记录来源、版本或 SHA-256；
- Open Babel 输入只接受单个、最大 10 MB 的 `smi/smiles/sdf/mol/mol2/pdb` 配体；多分子、超时、非零退出、工具报错、无效 PDBQT、全零或完全重合坐标一律不得生成可用配体；
- Open Babel 成功准备必须记录输入/输出 SHA-256、实际版本、可执行文件 SHA-256、受控参数、退出码和耗时；受体不进入该自动转换链；
- Agent 本机 Vina 执行仅在实际版本与任务清单一致、可执行文件哈希复核通过、退出码为 0 且日志与输出 PDBQT 合规时保存分数；成功任务留存版本、可执行文件 SHA-256、参数、退出码、耗时、绑定日志与输出 PDBQT SHA-256；
- 受体审批记录同时包含原始/准备后结构哈希、类型化身份、模型/链选择、
  altloc 策略、水与异源原子决策、准备工具和口袋依据；不能用名称或界面状态
  代替哈希绑定；
- 每个批量尝试的预测评分、seed、模式必须从同一组已验证日志和输出构象派生；
  不能把任意分数、日志或 pose 后配到可视化包；
- 3Dmol.js 从仓库固定资产加载；PyMOL、PLIP、Vina 和 Open Babel 均为外部
  可选工具，执行前必须满足身份核验与用户确认；
- PNG 必须完整解码验证；PSE 未通过同一已核验 PyMOL 重开验证时只能标记
  `generated_unverified`；PML 始终可编辑并保存自身 SHA-256；
- PDBQT→PDB 与 PLIP 输出具有启发式限制，可能丢失键级、电荷和原子类型；
  这些产物不得被表述为实验相互作用证据；
- 网络药理学和分子对接固定标记为 `computational_prediction`，不能写入直接文献或实验引用；
- 数据库记录、PPI 和富集结果按来源证据类型展示，不能被描述为已验证靶点、
  通路或因果机制；
- 合成演示数据必须带 `synthetic_demo` 标记，并在报告中声明不可作为科研证据；
- 缺失字段显示为空或“未报告”，不能由规则或模型补造；
- 用户导入题录、实验 CSV 和 `.workbench` 运行记录仅在本机处理，不提交仓库。

## 10. 风险与下一步

- 规则提取无法覆盖所有摘要表达方式；
- RIS、EndNote、RefWorks 的平台导出变体可能需要补充兼容样本；
- 摘要和题录常缺少剂量、时间、对照或完整实验方法；
- 当前冲突检测只识别显式效应方向，不能替代人工语义复核；
- FICI 阈值分类和生长曲线 AUC 都是描述性结果；
- LetPub 不是官方 API，分区信息需要正式复核；
- Open Babel 的通用 3D、pH 质子化和 Gasteiger 电荷不能替代对配体互变异构体、立体化学、质子化状态和构象的人工核查；受体始终由研究者准备；
- 本机 Vina 的结构准备和搜索框仍需人工核查；默认 Docker 镜像不含 Vina，容器执行必须另行提供兼容二进制文件；
- PDBQT→PDB 不能完整恢复化学键、电荷和原子类型，PLIP/三维图只能作启发式
  检查；多个 seed 的评分稳定不等于采样收敛，也不能替代分子动力学或实验；
- 当前本地快照恢复以完整运行 ID 作为访问凭证，仅支持可信单用户本机模式；共享部署前必须增加账号和对象级授权；
- 下一步应扩充经人工标注的公开正负案例和术语同义词，再决定是否增加全文解析或 LLM Provider。
