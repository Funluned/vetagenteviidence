# VetResearch Workbench v0.7 Agent 评测说明

## 现在做到哪一步

代码已经实现三部分：

1. `DeepSeekProvider`：只连接 DeepSeek 官方 Chat Completions 地址，记录模型、
   请求哈希、响应身份、Token、精确费用和失败尝试；默认费用上限为 0。
2. `Research Agent`：先规划，再调用受限工具找证据，最后只根据证据账本写草稿。
3. `Evidence Reviewer`：只读检查同一份草稿、证据账本和工具记录；它不能重新
   检索，也不能添加新证据。未通过时，对外只给安全拒答或人工复核状态。

真实 DeepSeek V4 Pro 已完成 5 个代表场景的受控试跑，并针对试跑发现的
`TOOL-02` 缺陷完成一次定向复测。因此现在可以证明真实 LLM 确实参与了受限的
Research Agent／Evidence Reviewer 工作流，但不能把小样本合成评测写成完整
模型效果或科研正确率。免费默认工作台没有改变：不配置模型和 Key，规则流程与
本地关键词检索仍可使用。

## “先从本地资料里找证据”具体指什么

在真实产品资料中，本地 RAG 只读取两类内容：

- 当前任务中已经取得的 PubMed 题录与摘要；
- 用户明确确认有权使用并主动导入的题录或摘要。

系统不会扫描任意电脑文件夹，也不会把整块硬盘当知识库。检索结果保留来源 ID、
PMID／DOI、切片 ID、原文和 SHA-256。Research Agent 写出的每条声明还必须保留
适用范围和原文引句；找不到足够证据就拒答。

本次 27 题评测使用的是仓库内冻结的合成资料，不是真实论文。送给 Provider 的
内容会把内部来源改名为 `source-001` 等中性别名；case 分类、标准答案、评分词、
`SYN-*` 标识和原始测试 URL 都不会进入模型可见内容。标准答案只留在评分器一侧。

## Agent 的硬边界

- Research Agent 每题最多 3 个计划项、4 次工具调用、2 次正常模型调用和 1 次
  结构修复重试；
- 工具只有 PubMed 检索、本地 RAG、FICI、生长曲线和报告生成五类，参数使用
  严格结构校验；不接受 Shell、任意本机路径、任意 URL 或可执行代码；
- Evidence Reviewer 每题最多 2 次审查、1 次定向修订和 1 次格式重试；它读取
  同一份证据账本、已验证计划和白名单化工具摘要，失败消息、任意工具输出与
  本机路径不进入 Reviewer；修订只能改被点名的声明，不能增加声明、来源或引句；
- 单 Agent 和双 Agent 共用同一次 Research 运行。Reviewer 看到的是同一份检索
  结果，因此双 Agent 不会靠多检索一次获得不公平优势；
- DeepSeek 的所有角色共用一个人民币硬上限。Provider 自身不做隐式 HTTP 重试；
  超时或已发出但无法核账的请求按保守预留费用计入上限；
- Key 只从 `DEEPSEEK_API_KEY` 环境变量读取，不写入结果、审计或日志。

## 真实 DeepSeek 五题试跑与定向复测

2026-08-02 使用 `deepseek-v4-pro` 跑了 `DIR-01`、`NONE-01`、`INJ-01`、
`SCOPE-01`、`TOOL-02` 五个合成工程场景。首次结果保存为
`data/eval/v0.7/results/agent_deepseek_deepseek-v4-pro_20260801T164712078981Z.json`，
结果 SHA-256 为
`f3a4e0d5b74548b12765f5cb981c4b670066f5afa5f525a2f1471a4f9afc654d`：

- 同五题规则基线 `3/5`，真实单 Agent `4/5`，真实双 Agent `4/5`；
- 单／双 Agent 共同达到 Citation Precision `1/1`、Unsupported Claim Rate
  `0/1`、Abstention Accuracy `4/4`、Task Completion `5/5`；Recall 为 `2/3`；
- 共 14 次真实模型调用和 14 次 HTTP 尝试，全部成功；输入／输出／推理 Token
  为 `7,286 / 5,324 / 4,468`，实际总费用 `¥0.0488516`；
- Reviewer 增加 `¥0.017358`，但五题全部批准，未改变单 Agent 的 `4/5`。

首次试跑真实暴露了两个关联缺陷：`TOOL-02` 只规划了一路检索，因此后两路没有
执行；Reviewer 当时只收到草稿和证据账本，没有收到可读的计划与工具状态，因而
错误批准。修复没有读取 gold 或硬编码批次数量，而是加入通用约束：用户明确要求
多路检索时必须拆成独立计划项，一路失败不得取消后续计划；Reviewer 读取白名单化
计划／工具摘要和完整轨迹哈希，未知模式与错误码统一降为不泄密的分类值。

随后只复测失败的 `TOOL-02`，没有重复花费运行其余四题。结果保存为
`data/eval/v0.7/results/agent_deepseek_deepseek-v4-pro_20260801T170517725369Z.json`，
结果 SHA-256 为
`7e0e47360e0f0a4820d0c884f5056aa01f3990e331e436053835cbac76d7c4d8`：

- 三路工具状态为“成功—失败—成功”，两个成功结果都被保留，失败批次为 1，
  `partial_results_preserved=true`，Recall `2/2`；
- 单 Agent 与双 Agent均通过；Reviewer 明确看见失败路线后批准；
- 共 3 次真实模型调用，输入／输出／推理 Token 为 `2,602 / 3,436 / 2,953`，
  实际费用 `¥0.0276604`；其中 Reviewer 增量为 `¥0.009351`；
- 两轮真实运行累计 17 次模型调用、17 次 HTTP 尝试，总费用 `¥0.0765120`，
  远低于批准的 `¥3` 硬上限。

其余四题没有在修复后的提示词版本上重跑，因此不能把两份不同版本的报告拼成
正式“`5/5`”。两份结果只证明合成场景下的真实调用、缺陷发现和定向回归，不是
真实论文、临床结论或领域专家验收。

最终零费用验证：Agent 专项 `76 passed`；全量 `602 passed, 1 skipped`；规则、
RAG、Agent 三套基线匹配；Python 编译、依赖、Git 差异、两份结果结构和敏感
信息扫描均通过。最终只读安全复核没有剩余高、中等级问题。

## 真实 DeepSeek 运行门禁

真实模式不会默认运行。必须同时明确选择题目、确认付费运行、给出正数人民币
上限并配置 Key；缺任何一项都会在 Provider 构造和网络请求之前停止。真实结果
使用带 UTC 时间戳的新文件，拒绝覆盖已有结果。

五题运行前的零费用预检命令：

```powershell
.\.venv\Scripts\python.exe scripts\run_v07_agent_evaluation.py `
  --provider deepseek `
  --case-id DIR-01 --case-id NONE-01 --case-id INJ-01 `
  --case-id SCOPE-01 --case-id TOOL-02 `
  --dry-run --max-cost-cny 3
```

它只读取冻结的本地评测文件，不读 Key、不构造 Provider、不联网。该预检估算
五题通常需要 15 次逻辑模型调用，所有格式重试和修订都走满时最多 35 次；首次
实际运行用了 14 次。每次新的真实运行仍须重新取得费用和范围确认，不能因为本次
试跑已获批准而自动继续调用。

价格快照复核于 2026-08-02，来源为
[DeepSeek 官方定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：
V4 Pro 缓存命中输入／缓存未命中输入／输出分别为每百万 Token
`¥0.025 / ¥3 / ¥6`。模型名称与接口要求见
[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。
实际费用按 API 返回的 Token 用量核算；接口未返回可核验用量时采用保守计费，
不会把不确定调用当成免费。

同一官方页面目前还预告了高峰时段 2 倍价格，但写的是“即将采用”，没有给出
正式生效日期。每次真实运行前必须重新核价；如果届时已经生效，就按 2 倍价格
保守折算或改在非高峰运行，不能突破大壮批准的总费用上限。

## 评测结果能证明什么

本次真实试跑证明 DeepSeek 确实参与了受限 Research Agent 和 Evidence Reviewer
工作流，并能在同一套七项指标下记录质量、成本、耗时和失败。它还证明真实运行
能发现 Fake 合同烟测没有暴露的规划与审阅缺陷。它仍然不能证明临床有效、科研
结论正确、全文检索完整，或真实用户材料已通过领域验收。
