# VetResearch Workbench v0.7.0 面试讲解与追问

## 60 秒项目介绍

“VetResearch Workbench 是一个面向兽医科研证据整理的本地工具。免费默认路径
通过 NCBI 获取 PubMed 题录和摘要，用透明规则完成证据分级、字段提取、FICI／
生长曲线分析和带来源报告；用户还可以把授权摘要建立为本地 SQLite 索引，默认
用关键词 BM25 检索 Top 3 待审查片段，不需要模型 Key。为了验证 LLM、RAG 和
Agentic Workflow，我另外实现了 DeepSeek V4 Provider、有限状态 Research Agent
和只读 Evidence Reviewer，并用 27 道九类合成工程题记录引用、拒答、成本、延迟
和失败。一次修复后全量中 Reviewer 拦住了一条问题声明并改善部分质量指标，但
历史批次不稳定，而且始终更贵、更慢，所以只保留为实验模式。整个项目只整理
证据，不提供诊断，也不把合成评测写成科研结论。”

## 常见追问

### 1. 这是不是 RAG？

需要分三层回答：

- 免费工作台已经实现“授权摘要 → 本地切片与索引 → Top 3 候选”，但到候选检索
  为止，不自动生成科研结论；
- Agent 合成评测会让真实 DeepSeek 根据冻结检索证据生成带引用草稿，因此具备
  检索增强生成的工程闭环；
- 当前所谓向量是确定性字符／词特征哈希，不是语义 Embedding。固定候选池
  Recall@3 为关键词 `4/5`、特征哈希 `2/5`、混合 `3/5`，所以不能宣传“语义
  RAG 已有效”或“混合检索优于关键词”。

### 2. 为什么免费路径仍然使用规则？

规则路径无需 Key、没有模型 API 费用，字段来源、准入理由和失败位置都可见。
它适合做默认产品底座。DeepSeek 用于隔离的开发者评测，证明项目真实开发过
LLM Agent，并测量模型波动、成本和失败；它不替代规则和人工复核。

### 3. Agent 是真的，还是几个 Prompt 文件？

模型调用是真的。Research Agent 有类型化状态，会先规划，再调用五类白名单
工具，最后只能根据证据账本写草稿；计划、工具、重试、Token 和费用都有硬上限。
Evidence Reviewer 使用第二个模型角色，只读检查同一次 Research 的草稿、证据和
工具摘要，不能重新检索或添加来源。

但工具数据当前来自冻结合成 PubMed 批次、临时本地索引和内存实验 CSV。仓库
尚未交付“任意用户问题 → 实时 PubMed／私有工作台资料 → Agent 报告”的产品
适配器，也没有 MCP 或 Codex Skill 接口。

### 4. 如何限制幻觉和错误引用？

- 每条声明必须带适用范围、来源 ID、切片 ID 和原文引句；
- 只有 `direct_interaction` 或合法的 `validated_experiment` 能支撑目标交互结论；
- 仅有背景或范围不匹配证据时，在生成前直接拒答；
- 账本外引用只允许一次限定在现有账本内的修复，不能增加新来源；
- Reviewer 执行同一确定性证据门禁，未批准时只返回安全拒答或人工复核状态。

这些措施降低风险，但不能证明模型不会犯错，也不能替代全文、原始数据和领域
专家复核。

### 5. 27 道题的成绩应该怎么讲？

- 规则基线：`20/27`；
- 当前 Fake 单／双 Agent：均为 `25/27`。Fake 只检查编排和合同，不是 LLM；
- 历史全 27 题真实 DeepSeek 报告按旧 scorer 记录单／双均为 `24/27`；修正
  scorer 对同一历史输出离线重算均为 `22/27`；
- 发布收口第一次独立全量为单／双 `26/27`、`25/27`；据此修复两个确定性缺口后，
  第二次独立全量为 `23/27`、`24/27`，两个修复点均通过；
- 两次全量费用分别为 `¥0.4456658`、`¥0.4318394`，累计 `¥0.8775052`。

所以当前代码的正式复测口径应说“本次单／双为 23/27、24/27”，同时说明模型采样
波动和失败类别；不能把不同版本、定向或全量结果拼分。27 道题都是合成工程夹具，
gold 仍待领域专家复核。

### 6. 双 Agent 是否比单 Agent 好？

不能下这个结论。第二次全量中，Reviewer 把 Citation Precision 从 `0.75` 提到
`1.00`、Unsupported Claim Rate 从 `0.25` 降到 `0`、Abstention Accuracy 从
`0.92` 提到 `0.96`，并多通过一题；但 Recall 和 Task Completion 不变，三个
规划／工具失败仍与单 Agent 共享，同时增加 `¥0.2480774` 和约 13.62 秒单题中位
耗时。历史批次还出现过无提升和反向退化，因此只能说“受限 Reviewer 在本批拦住
了一条问题声明”，不能说“多 Agent 稳定更好”，当前只保留实验模式。

### 7. 真实评测暴露过哪些问题？

- 模型引用了证据账本外的来源，系统安全拦截；
- 冲突证据被模型误写成“证据不足”；
- 草稿 JSON 不符合严格 schema；
- 计算预测被误当成直接交互证据；
- 检索词漏掉研究实体；
- 2048 output Token 被 reasoning 用尽；
- DeepSeek JSON Output 提示漏掉必需的 `json` 字面量而收到 HTTP 400；
- 修复后全量中，模型在明确写着“三路检索”的题目上只规划两路，也在明确要求
  FICI 且提供受信 dataset ID 时漏掉 `experiment.fici`。两题最终安全拒答，说明
  当前主要剩余限制是规划完整性，而不是证据门禁失效。

这些问题分别促成了引用修复边界、冲突 scorer、问题级证据等级、检索实体补齐、
2048→4096 单次有界恢复和 JSON 契约回归测试。最后两项没有为追求分数而让运行时
替模型自动补齐所有研究步骤，因为“能否选对所需工具”本身就是本轮 Agent 能力的
被测对象；它们作为 v0.7.0 已知限制保留。

### 8. 这是生产级科研或医疗 AI 吗？

不是。它是可信单用户本机的工程原型，主要处理题录和摘要，不批量读取全文；
没有企业账号权限、多租户、服务 SLA 或真实用户 Agent 工作流验证。规则、RAG、
Agent 和计算预测都不能证明临床有效性、药物协同或科研结论正确。

### 9. 为什么不用 FastAPI 或云向量数据库？

当前只有一个本地 Streamlit 客户端，来源规模上限为 500 个摘要、500 万字符，
SQLite 已满足可追溯索引和恢复。增加服务层或云向量库会扩大部署、费用和权限
边界，但不会自动提高证据质量。出现多个客户端、共享部署或真实 API 消费者后
再拆分更合理。

### 10. 下一步是什么？

当前正在完成 v0.7.0 的 GitHub 工程收口。合并、Tag、Release 和仓库设置稳定后，
再进入已经明确延期的本人验收：从零安装、架构讲解、一次小修改和排错。只有
目标升级为
普通用户可用的生成式 Agent 时，才新增真实工具适配器、任意问题入口、用户凭据
方案和真实授权材料试点；这属于新的产品开发范围。
