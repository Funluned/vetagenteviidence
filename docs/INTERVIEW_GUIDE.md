# 面试讲解与追问

## 60 秒项目介绍

“VetEvidence AI 是一个面向兽医科研场景的证据整理工具。用户输入药物、病原菌或疾病模型后，系统通过 NCBI API 检索真实 PubMed 文献，解析标题、摘要、PMID 和 DOI，再把摘要中明确报告的物种、模型、样本量、剂量、结果和机制整理成 Pydantic 结构。回答中的每条结论都保留 PMID、DOI 和来源原句，未报告字段为空。当前版本使用透明规则，所以不依赖 LLM Key；我还建立了自动测试和 30 条定向评测，并明确记录小样本和摘要级证据的局限。”

## 常见追问

### 1. 这是不是 RAG？

具备“检索真实来源并基于检索上下文回答”的核心流程，但当前没有向量检索。数据量较小，直接使用 PubMed 查询和摘要上下文更简单、可解释。

### 2. 为什么不用大模型？

第一版先验证数据源、字段、引用和评测。规则 Provider 在无 Key 时也能工作，并能明确看出每个字段为何被提取。后续可以增加 LLM Provider，但必须经过相同结构化校验。

### 3. 如何防止幻觉？

缺失字段为 `None`，回答只复用证据记录中的来源结论，并关联 PMID、DOI 和原句。评测包含未报告字段保持为空和无证据拒答。

### 4. 评测 100% 是否可信？

它只是 30 条定向工程检查，集中在一个真实示范查询和少量受控边界，不代表通用准确率。下一步要扩大病原、物种、药物和人工全文标注。

### 5. 遇到过什么错误？

- 检索词过窄导致 PubMed 返回 0 条；
- Streamlit 热重载保留旧模块缓存；
- 评测器分支顺序错误导致两条引用检查误判。

每个问题都有复现、修复和回归测试。

### 6. 为什么不用 FastAPI？

第一版只有单个 Streamlit 客户端，拆成服务会增加部署复杂度但不提升证据质量。等出现多个客户端或正式 API 消费者再拆分。

### 7. Docker 解决什么？

固定 Python 和依赖安装流程，减少“在我的电脑能运行”的环境差异。本机目前未安装 Docker，所以 Dockerfile 已写但镜像构建尚未验证。

### 8. 下一步怎么做？

先增加多主题人工标注集和全文合法接入，再比较规则与 LLM Provider 的字段准确率、引用支持度、成本和延迟。
